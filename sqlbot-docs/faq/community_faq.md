## 2 数据源管理

### 2.1 SQL Server低版本中文乱码如何解决

**问题**：SQL Server 低版本数据源出现中文乱码，添加 charset=GBK 等配置无效怎么办？

**处理方式**：

请区分「连接失败」与「中文乱码」两类问题：

1. **连接失败（连不上旧版 SQL Server）**：数据源配置中提供「兼容低版本」选项。存量数据为保证可用性默认选中，新建时默认不选中。若连接失败，可按需勾选。注意：勾选「兼容低版本」后无法设置编码，**不能**用来解决乱码。
2. **中文乱码**：一般不要依赖「兼容低版本」。`nvarchar` 类型通常不存在乱码；若为 `varchar` 类型且排序规则为 `Chinese_PRC`，可在额外连接参数中添加 `charset=GBK`。另请注意：`varchar` 与 `nvarchar` 不可混用。

若已勾选「兼容低版本」导致无法设置编码，可先关闭该选项后再配置 `charset=GBK`（需确认关闭后以能正常连接）。

## 3 智能问答与助手

### 3.1 示例SQL因表召回限制未生效怎么办？

**问题**：编写了示例 SQL，但因涉及表数量较多，部分表未被召回导致 SQL 执行失败，如何处理？

**处理方式**：

可按以下步骤排查与优化：

1. 在【数据源】-【表管理】中确认示例 SQL 用到的表均已启用，并补充必要的表/字段描述。
2. 在【数据源】-【表关系管理】中维护相关表的关联关系，便于模型正确生成跨表 JOIN。
3. 若数据源表数量较多，可精简纳入问数范围的表，或将过复杂的示例拆成涉及更少表的多条示例 SQL，降低召回遗漏概率。

## 4 系统集成与权限

### 4.1 统一认证集成如何开启自动创建用户

**问题**：SQLBot 集成统一认证后，是否有开关可以开启自动创建用户？

**处理方式**：

该能力属于企业版（X-Pack）。在「登录认证设置」中开启「第三方自动创建用户」开关即可。该设置用于控制外部系统（如平台对接、单点登录）接入 SQLBot 时是否自动创建用户账号；默认关闭，需手动开启。

详细配置步骤请参阅[参数配置](../enterprise/third-party-platform-settings.md)
