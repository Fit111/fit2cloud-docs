本页汇总 DataEase 技术交流群中用户咨询频率较高的常见问题及处理方式，内容持续更新。

## 1 安装部署

### 1.1 V2能否直接升级到V3

**问题**：DataEase V2 能否在同一台服务器上直接升级到 V3？

**处理方式**：

不支持直接升级。V2 与 V3 架构不兼容，安装脚本会检测当前版本并阻止升级。需在新环境安装 V3，并使用官方迁移工具将 V2 数据迁移至 V3。

迁移步骤请参阅[V2-V3 数据迁移指南](../installation/data_migration.md)

### 1.2 外部数据库安装后缺表或Schema配置错误怎么办？

**问题**：使用外部数据库（如PostgreSQL）进行脚本化安装时，提示缺表或Schema配置错误，应如何修正？

**处理方式**：

DataEase 安装脚本会自动在目标库中建表并写入初始数据。若出现缺表或 Schema 错误，通常是因为 `install.conf` 中的 `DE_DB_SCHEMA` 配置不正确或为空。

请在安装目录的 `install.conf` 文件中修改 `DE_DB_SCHEMA` 为正确的 Schema 名称（PostgreSQL 默认为 `public`，若未指定则可能默认为用户名或空），保存后执行 `dectl restart` 重启服务。

详细配置参数请参阅[外部数据库部署](../installation/multi_database_deployment.md)

### 1.3 V3 能否装在原有系统上做迁移？

**问题**：DataEase V2 做数据迁移时，V3 必须装在新系统上，还是可以装在原有系统？

**处理方式**：

可以装在原有系统，也可以装在新系统，迁移工具不要求 V3 与 V2 分处不同服务器。

迁移工具通过网页填写源端与目标端信息，支持本地到本地、本地到远程、远程到本地、远程到远程；源端与目标端安装目录默认分别为 `/opt/dataease2.0`、`/opt/dataease3.0`。唯一硬性限制是源库与目标库不能是同一个库，且目标库会被删除并重建。

详细步骤请参阅[V2-V3 数据迁移指南](../installation/data_migration.md)

## 2 数据源与数据集

### 2.1 跨源查询 Doris 报错怎么办？

**问题**：在多源跨源查询时，Doris 数据源因自动添加的分页语法不支持而报错，该如何处理？

**处理方式**：

在近期版本中，为了修复安全漏洞，系统将 MySQL/Doris 类数据源的底层驱动切换为了 MariaDB 驱动。驱动替换后，跨源计算引擎（Calcite）在识别数据库元数据时未能准确匹配到 MySQL/Doris 方言，回退到了默认的 ANSI 标准方言，生成了 OFFSET ... FETCH ... 分页语法，导致 Doris 执行时出现语法解析错误。
该问题已修复，将在后续版本（v2.10.28 及 v3.2.0）中发布。

### 2.2 V3 是否支持跨源查询？

**问题**：DataEase V3 是否支持跨源查询？

**处理方式**：

V3 不支持跨源查询。跨源涉及不同数据库，存在兼容性问题，因此 V3 已将该功能去掉；V2 支持跨源。

### 2.3 自定义SQL数据集保存提示超时怎么办？

**问题**：创建自定义 SQL 数据集时，SQL 能运行出结果，但保存时一直提示超时，是什么原因？

**处理方式**：

保存时的超时由数据源的查询超时时间控制，需到对应数据源的「高级设置」中调大查询超时时间。

## 3 仪表板与图表

### 3.1 日期范围筛选器能否手动输入日期？

**问题**：日期范围筛选器跨年度选择日期很麻烦，能否手动输入开始和结束日期？

**处理方式**：

目前不支持手动输入日期。可使用时间范围查询组件左侧的快捷日期选择方案：需将组件类型设为「时间范围」，时间粒度选择「年月日」，此时左侧会提供本周、本月、本季度等常用区间快捷选项。
